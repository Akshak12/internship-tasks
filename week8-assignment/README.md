# E-Commerce Order Analytics System

A robust Python + SQLite data pipeline that generates raw e-commerce data with intentional anomalies, cleanses it using Pandas, loads it into a SQLite database, and provides advanced analytical SQL reporting capabilities.

---

## Architecture Overview

The system runs a complete ETL (Extract, Transform, Load) pipeline:
1. **Extract**: Generates raw transaction logs as CSV files with specific realistic anomalies.
2. **Transform**: Normalizes names, cleans data types, validates emails, checks referential integrity, and filters out erroneous rows while preserving returns (negative quantities).
3. **Load**: Recreates the schema in a local SQLite database (`freshmart.db`) and loads the cleansed datasets with full constraint enforcement.
4. **Analyze**: Contains advanced SQL queries (CTEs, Window Functions, cohort analyses) for business intelligence.
5. **CLI Reporting**: A standard-library-only interactive CLI tool to view aggregate performance metrics.
6. **Report Generation**: Runs SQL analytics queries and saves formatted outputs directly in the reports output directory.

## Schema Realignment

* **`customers`**: `customer_id` (PK), `customer_name`, `email`, `registration_date`, `customer_type` (`REGULAR`, `PREMIUM`, `VIP`)
* **`products`**: `product_id` (PK), `product_name`, `category`, `subcategory`, `cost_price`
* **`orders`**: `order_id` (PK), `customer_id`, `order_date`, `status` (`PLACED`, `SHIPPED`, `DELIVERED`, `CANCELLED`, `RETURNED`), `region_code`
* **`order_items`**: `item_id` (PK), `order_id` (FK), `product_id` (FK), `quantity`, `unit_price`, `discount_percent`

## Pipeline Anomalies Cleansed

| Anomalous Case | Handling / Behaviour |
| :--- | :--- |
| `order_items` references non-existent order / product | Dropped during referential integrity checks |
| `discount_percent` is invalid (e.g. >100 or <0) | Reset to `0.0%` |
| `quantity` is exactly 0 | Dropped as a non-transactional record |
| `quantity` is negative | **Preserved as a return** (subtracted from revenues in SQL analytics) |
| `order_date` is in the future | Dropped to prevent premature order tracking |
| Non-standard date formats (e.g. `DD-MM-YYYY`) | Automatically parsed and normalized to standard ISO `YYYY-MM-DD HH:MM:SS` |
| Product names contain extra spaces or weird cases | Trimmed and standardized to `Title Case` |
| Customer emails missing `@` or domain | Tracked, reported, and logged under email anomalies |

## How to Run the Pipeline

### 1. Install Dependencies
Only `pandas` and `faker` are needed for the data generation and cleaning stages:
```bash
pip install pandas faker
```

### 2. Synthesize Raw Data
```bash
python scripts/generate_data.py
```

### 3. Clean and Build Database
```bash
python scripts/clean_data.py
```

### 4. Run Verification Tests
```bash
python testedge_cases.py
```
